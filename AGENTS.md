# CareBridge Architecture Rules

> **Read this file on every session.** These rules are non-negotiable.
> Violating them breaks integration between the 5 agents built in parallel.

---

## 1. AGENT BOUNDARIES

Each agent has a strict scope. Do not add tools or responsibilities outside that scope.

- **Supervisor Agent:** orchestrates only. Never calls external APIs directly. Never executes
  specialized agent tools itself. Routes, classifies, audits, escalates.
- **Medication Agent:** pharmacy tools only. Never schedules appointments. Never sends
  family alerts. Never touches delivery.
- **Appointment Agent:** calendar tools only. Never orders refills. Never sends family
  alerts. Never touches delivery.
- **Logistics Agent:** delivery tools only. Never sends family alerts. Never modifies
  medication or appointment data.
- **Communication Agent:** messaging tools only. Never modifies care data. Never calls
  pharmacy, calendar, or delivery APIs.

---

## 2. INTER-AGENT COMMUNICATION

- All communication routes through the Supervisor Agent.
- No direct agent-to-agent calls (no `medication_agent.call(appointment_agent)`).
- Specialized agents return structured Pydantic models only — never free-form strings.
- Supervisor wraps each specialized agent as a callable tool via Strands agents-as-tools
  pattern (`tools=[medication_agent, appointment_agent, ...]`).
- All actions logged to the audit trail BEFORE execution.

---

## 3. FORBIDDEN — NEVER DO THESE

- **Never modify** `src/models/audit_log.py` — the audit schema is immutable.
- **Never bypass** `src/models/escalation_logic.py` — this is safety-critical.
- **Never** let an LLM classify an action as autonomous vs. requiring approval. Use the
  deterministic `classify_action()` function.
- **Never** write to the audit trail AFTER executing an action. Always BEFORE.
- **Never** catch an exception silently. Every failure must be logged and either retried
  or escalated.
- **Never** commit `.env` files or hardcode API keys, tokens, or secrets.
- **Never** make clinical decisions (diagnose, prescribe, alter treatment). The agent
  coordinates; it does not practice medicine.
- **Never** call an external API without first writing a "before action" entry to the
  audit trail.

## 5. CODE STYLE

- **Python version:** 3.11+
- **Type hints:** required on all function signatures and public methods.
- **Pydantic v2:** all data models use `BaseModel` with strict typing. Use `Literal` for
  enums, not raw strings.
- **Async:** I/O-bound tools (`order_refill`, `send_alert`, `schedule_appointment`) are
  `async def`. Pure logic tools (`classify_action`, `check_refill_status`) are sync.
- **Error handling:** every tool wraps external calls in try/except. On failure: log to
  audit trail with `outcome="failure"`, then re-raise or return a failure model.
- **Retries:** use the shared helper `src/tools/retry.py` — 3 attempts, exponential
  backoff (1s, 2s, 4s). Do not implement custom retry loops.
- **Logging:** use `logging.getLogger(__name__)`. No `print()` in production code paths.
- **Imports:** absolute imports from `src.*`. No relative imports across subpackages.
- **Docstrings:** every public function has a docstring with Args, Returns, Raises.

## 7. AUDIT TRAIL RULES

Every agent action produces exactly one audit event with these fields:

| Field | Required | Notes |
|---|---|---|
| `event_id` | yes | UUID v4, generated by `write_audit_event()` |
| `timestamp` | yes | UTC ISO 8601, generated by `write_audit_event()` |
| `actor` | yes | One of: `supervisor`, `medication`, `appointment`, `logistics`, `communication`, `human` |
| `action_type` | yes | Tool name (e.g., `order_refill`, `send_alert`) |
| `care_recipient_id` | yes | FK to care recipient |
| `rationale` | yes | Why the agent took this action — one sentence, plain language |
| `outcome` | yes | `success` \| `failure` \| `pending` \| `escalated` |
| `correlation_id` | yes | UUID shared across all actions for the same event |
| `authorization_ref` | if applicable | ID of the human approval that authorized this action |

**Rule:** write the "before action" event with `outcome="pending"` BEFORE executing.
Update via a follow-up event with the final outcome — do not UPDATE the original row
(SQLite triggers prevent UPDATE/DELETE).

## 8. ESCALATION RULES

Classification is deterministic — use `classify_action()` in `src/models/escalation_logic.py`.

| Category | Actions |
|---|---|
| **AUTO** | `check_refill_status`, `check_delivery_status`, `get_calendar`, `synthesize_status`, `send_daily_digest` |
| **ALERT** | `order_refill`, `order_grocery`, `schedule_appointment`, `order_pharmacy_delivery` |
| **APPROVE** | `cancel_appointment`, `change_medication_schedule`, `add_service_provider`, `modify_health_record` |

**Escalation levels:**

- `info` — routine update, batch into daily digest
- `alert` — SMS to primary caregiver + email to others
- `emergency` — SMS + email + phone call to ALL family members in escalation order

**Emergency triggers (hard-coded, not LLM-decided):**

- Fall detection signal
- Emergency room visit notification
- Critical medication interaction detected

---

## 9. FAILURE RECOVERY

- External API call fails → retry 3× with exponential backoff (1s, 2s, 4s)
- After 3 failures → escalate with `level="alert"`, log `outcome="escalated"`
- Every integration must have a documented fallback:
  - **Pharmacy API unavailable** → generate manual refill reminder for caregiver
  - **Messaging API unavailable** → queue alert in dashboard only
  - **Calendar API unavailable** → log to audit + notify caregiver to schedule manually
  - **Delivery API unavailable** → notify caregiver to place order manually
- Never silently fail. Never assume success.

---

## 10. SECURITY

- All secrets via environment variables (`.env`, never committed)
- JWT auth required for all caregiver-facing API endpoints
- Tool whitelisting: each agent declares only the tools it needs
- All sensitive operations (category `approve`) require explicit `authorization_ref`
- PII (names, addresses, phone numbers) never appears in log output
- Audit trail entries reference IDs, not raw PII

---

## 11. TESTING

- Every tool function has at least one unit test
- Every agent has at least one integration test covering happy path + failure path
- Retry logic is tested with a mock that fails N times then succeeds
- Escalation logic is tested for all three categories (auto / alert / approve)
- Audit trail is tested for immutability (attempt UPDATE → expect exception)
- Mock data lives in `fixtures/*.json`, never inline in test files

---

## 12. COMMIT HYGIENE

- One logical change per commit
- Commit message format: `<area>: <what changed>` (e.g., `medication: add retry to order_refill`)
- Never commit `logs/`, `.env`, `audit.db`, `__pycache__/`, `node_modules/`
- Run `pytest tests/` before every commit

---

## 13. WHEN IN DOUBT

If a subagent is unsure whether an action belongs to its scope:

1. Do NOT take the action
2. Return a structured "not my scope" result to the Supervisor
3. Supervisor routes to the correct agent
4. Log the routing decision to the audit trail

**Do not guess. Do not improvise. Follow the spec.**
