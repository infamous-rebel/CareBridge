Two-layer design under `src/agents/` and `src/tools/`. The `supervisor_agent.py` is the single entry point (`process_event`, `approve_pending_action`, `query_status`) that routes incoming `CareEvent`s via `_route_to_agent` to one of four domain agents (`medication_agent`, `appointment_agent`, `logistics_agent`, `communication_agent`). Each agent exposes an async `handle_<domain>_event(CareEvent)` handler that composes domain-specific tool calls from the matching `tools/<domain>_tools.py` module. Escalation decisions are fully deterministic: the Supervisor combines hard-coded emergency triggers, `classify_action()` from `src/models/escalation_logic.py`, and agent-reported flags — never LLM-decided. All side-effecting tool functions follow an audit-first pattern: they write a `pending` audit event via `write_audit_event` before execution and a follow-up `success`/`failure` event after, linked by a correlation id. External API calls go through `tools/retry.with_retry`, which wraps sync or async callables with 3 attempts and exponential backoff (1s, 2s, 4s) raising `RetryExhausted` on exhaustion. A Strands SDK integration (`create_supervisor_agent`) is optional and gracefully degrades to direct routing when unavailable. Dependency direction is strictly agents → tools → models; tools never import agents.
