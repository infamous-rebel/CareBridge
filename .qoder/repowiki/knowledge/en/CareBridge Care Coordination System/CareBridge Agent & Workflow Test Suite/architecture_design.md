Tests are split into two layers under `tests/`: unit-level files (`test_supervisor.py`, `test_medication_agent.py`, `test_appointment_agent.py`, `test_communication_agent.py`, `test_logistics_agent.py`) target individual agents and tools via direct imports from `src.agents.*` and `src.tools.*`; the `tests/integration/` subpackage contains end-to-end flows (`test_approval_flow.py`, `test_escalation_flow.py`, `test_refill_flow.py`) that exercise the full supervisor routing pipeline. All tests share a `temp_audit_db` pytest fixture (injected via conftest) to isolate SQLite-backed audit log writes, and static reference data lives in `fixtures/*.json` (appointments, medications, family_members, delivery_history) consumed by the source code under test rather than directly by assertions. Tests import domain schemas (`CareEvent`, `ResolutionResult`, `RefillStatus`, etc.) from `src.models.schemas` and assert behavior through those typed return values plus audit-log queries.
