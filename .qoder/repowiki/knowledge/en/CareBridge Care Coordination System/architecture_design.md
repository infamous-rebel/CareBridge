The root `main.py` is the single process entry point that wires together the three child modules: it calls `src.models.audit_log.init_audit_db()` to create the shared immutable SQLite audit database, loads JSON fixtures from `fixtures/` (medications, appointments, delivery_history, family_members) that all agents consume, then creates the Supervisor Agent via `src.agents.supervisor_agent.create_supervisor_agent()` which composes the Medication, Appointment, Logistics, and Communication agents as tools. The demo scenario in `run_demo_scenario()` drives the four care events through `process_event`, producing `ResolutionResult` objects defined in `src.models.schemas`. All cross-child communication flows through these shared contracts — `CareEvent` / `ResolutionResult` schemas, the audit log, and the deterministic escalation classifier — so agents never call each other directly but coordinate exclusively via the Supervisor. Pytest configuration in `pyproject.toml` (`asyncio_mode = auto`, `testpaths = tests`) provides the unified test harness used by the tests module to exercise the same agent routing and audit pipeline.
